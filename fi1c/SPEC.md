# FinIskaziCG — спецификация внешней обработки

Внешняя обработка 1С для формирования годовой финансовой отчётности Черногории (FI — finansijski iskazi)
и декларации по налогу на прибыль (PD) с выгрузкой в XML для портала eprijava.tax.gov.me / IRMS,
а также в XLSX/PDF.

## Окружение

- Конфигурация: **1С:Бухгалтерия КОРП МСФО 3.3.3.27** (типовая, фирма «1С»), управляемое приложение.
- Платформа: **8.3.27.1859**, клиент-серверная, сервер `navus-server`.
- Учёт РСБУ на плане счетов `Хозрасчетный`; черногорский контни оквир живёт в плане счетов **`МСФО`**
  (коды = черногорские: 010, 202, 433, 60x, 5xx…), проводки — в **`РегистрБухгалтерии.МСФО`**
  (заполняется трансляцией, данные есть по всем годам с 2022). Измерение `Организация`, ресурс `Сумма`.
  Валюта учёта EUR.
- В базе много организаций; неактивные помечены префиксом `ххх`/`xxx` в наименовании.
- PIB организации лежит в реквизите `ИНН` справочника `Организации`.

## Источники данных расчёта

- Остатки: `РегистрБухгалтерии.МСФО.ОстаткиИОбороты` / `Остатки` на конец года (`КОНЕЦПЕРИОДА(&Год)`).
- Обороты: за год по счетам классов 5/6.
- Счёт выбирается по ПРЕФИКСУ кода (например правило "01" включает 010, 011, 012…; "440-449" — диапазон).
- Правила маппинга строк отчётности: макет `ПравилаМаппинга` (JSON, см. mapping/mapping.json):
  секции → строки → kind (account|formula|manual|header), accounts {include, exclude, dio}, balance-тип, formula.
- Виды balance: debitNet (Дт−Кт остаток), creditNet, debitOnly, creditOnly, turnoverDebitNet, turnoverCreditNet.
- Формулы — выражения из RedniBroj той же секции со знаками + и −.
- Prethodna godina (Iznos2 в BU и т.п.) — тот же расчёт за Год−1.
- Семантика колонок каждой секции — см. research/fi_columns.md (результат рисёрча).
- (dio)-строки и manual-строки — через ТЧ «Корректировки» (см. ниже): рассчитанное значение
  плюс/вместо ручного.

## Структура обработки

Имя: `FinIskaziCG`. Синоним: «Финансијски искази ЦГ (FI + PD)».

Реквизиты:
- `Организация` — СправочникСсылка.Организации
- `Год` — Число(4,0)
- Поля заголовка FI (Zaglavlje): `СифраДјелатности`, `МатичниБрој`, `ЛицеНазив`, `ЛицеJMBG`, `ЛицеEmail`,
  `ОдгЛицеИме`, `ОдгЛицеПрезиме`, `ОдгЛицеJMBG` — Строка. Автозаполнение чем можем (наименование, ПИБ из ИНН),
  остальное руками; сохранять через ХранилищеСистемныхНастроек по ключу "FinIskaziCG/"+ПИБ.

Табличные части:
- `Строки` — рассчитанные строки всех секций: `Секция` (Строка), `RedniBroj` (Строка), `Позиция` (Строка),
  `GrupaRacuna` (Строка), `Iznos1..Iznos3` (Число 15,2), `Kind` (Строка), `Ручное` (Булево).
  (Капитал/амортизация с их множеством колонок — отдельные ТЧ `СтрокиКапитала` (Позиция, Опис, Iznos2..Iznos11),
  `СтрокиАмортизации` (Grupa, Iznos2..Iznos8) — заполняются manual/0 в v1, редактируемы на форме.)
- `Корректировки` — `Секция`, `RedniBroj`, `Колонка` (Число: 1/2/3), `Сумма` (Число 15,2), `Комментарий`.
  Применяются ПОСЛЕ расчёта: значение строки = рассчитанное + Сумма (для manual-строк рассчитанное = 0).
  Формульные строки пересчитываются после применения корректировок.
- `PDСтроки` — `Код` (Строка: "1".."59","15a"…,"PG1_1"…), `Наименование`, `Сумма` (Число 15,2),
  `Авто` (Булево). Автозаполнение из FI и формул (см. research/pd_lines.md), ручные строки редактируются,
  после правки — пересчёт формульных строк PD (кнопка).

Макеты (все — ТекстовыйДокумент, содержимое в UTF-8):
- `ШаблонFI` — копия xsd/fi.xml (все строки с RedniBroj/Pozicija/GrupaRacuna, суммы 0).
- `ШаблонPD` — копия xsd/pd.xml.
- `ПравилаМаппинга` — mapping/mapping.json.

## Экспортные функции модуля объекта (headless-API для тестов)

```bsl
Процедура ЗаполнитьПоПараметрам(ИмяОрганизации, Год) Экспорт      // находит организацию, ставит реквизиты, Заполнить()
Процедура Заполнить() Экспорт                                     // расчёт ТЧ Строки по маппингу+регистру, применение корректировок
Функция  ВыгрузитьXMLФИ(ПутьФайла) Экспорт                        // заполняет ШаблонFI значениями → пишет файл, возвращает путь
Функция  ВыгрузитьXMLПД(ПутьФайла) Экспорт
Функция  ВыгрузитьОтчет(ПутьФайла, Формат) Экспорт                // "XLSX"|"PDF" через ТабличныйДокумент.Записать
Функция  ПолучитьСтрокиJSON() Экспорт                             // {"BilanStanja":{"001":[i1,i2,i3],...},...} для кросс-чека
Функция  ПроверитьКонтроли() Экспорт                              // строка с расхождениями формул/балансов ("" если ок)
```

XML-выгрузка: читать шаблон из макета, подставлять суммы по (Секция, RedniBroj), формат чисел:
точка-десятичный разделитель, без группировки (`Формат(Х,"ЧРД=.; ЧГ=0")` + СтрЗаменить неразрывных пробелов).
Кодировка файла UTF-8. Выгруженный XML обязан валидироваться xsd/fi.xsd и xsd/pd.xsd.

## Форма (управляемая, одна)

- Шапка: Организация, Год, поля Zaglavlje (свёрнутая группа), каталог выгрузки.
- Кнопки: Заполнить, Проверить контроли, Выгрузить XML (FI), Выгрузить XML (PD), Excel, PDF.
- Страницы: «Отчёт» — ПолеТабличногоДокумента (красивый просмотр всех секций с итогами);
  «Корректировки» — таблица ТЧ Корректировки; «PD» — таблица ТЧ PDСтроки;
  «Капитал/Амортизация» — таблицы соответствующих ТЧ.
- Все вычисления — &НаСервере, вызовы методов объекта.

## Исходники и сборка

- Формат: XML-выгрузка внешней обработки (version 2.17), файлы в `src/`:
  `src/FinIskaziCG.xml` (корень), `src/FinIskaziCG/Ext/ObjectModule.bsl`,
  `src/FinIskaziCG/Forms/Форма.xml` (+ `src/FinIskaziCG/Forms/Форма/Ext/Form.xml` и `.../Form/Module.bsl`),
  `src/FinIskaziCG/Templates/<Имя>.xml` (+ `.../Template.txt` для текстовых макетов — по формату выгрузки).
- Все .xml/.bsl — UTF-8 **с BOM** (build.sh добавляет автоматически).
- Рабочий минимальный пример формата, принятый дизайнером 8.3.27: scratchpad/smoke (Smoke.xml + Ext/ObjectModule.bsl);
  ClassId внешней обработки: `c3831ec8-d8d5-4f93-8a22-f9bfae07327f`.
- Сборка: `./build.sh` → дизайнер на сервере → `C:\scripts\fi-epf\build\FinIskaziCG.epf`, лог ошибок показывается.
- Тест: AttachTest-подход — ДвоичныеДанные → ПоместитьВоВременноеХранилище → ВнешниеОбработки.Подключить(адрес,
  имя, Ложь, ОписаниеЗащитыОтОпасныхДействий) → Создать → вызовы экспортных функций.
  ВАЖНО: подключение по пути файла НЕ работает (rphost), только через временное хранилище.

## Ограничения v1 (осознанные)

- Tokovi gotovine (обе секции), Iskaz o promjenama kapitala, Statistički aneks (строки без GrupaRacuna),
  Obračun amortizacije — заполняются вручную/нулями, редактируемы; автоматизация — v2.
- (dio)-строки: вся сумма счёта падает в первичную строку, разнесение — корректировками.
- PD: авто — перенос прибыли из FI, формульные цепочки, прогрессивный налог; льготы/кредиты/переносы убытков — руками.
