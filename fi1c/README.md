# fi1c — FinIskaziCG: годовая отчётность Черногории из 1С

Внешняя обработка для **1С:Бухгалтерия КОРП МСФО** (8.3.27): считает годовую финансовую
отчётность Черногории (FI — finansijski iskazi) и декларацию по налогу на прибыль (PD)
из регистра бухгалтерии **МСФО** (черногорский kontni okvir) и выгружает:

- **XML** для портала налоговой (eprijava.tax.gov.me / IRMS) — форматы `xsd/fi.xsd`, `xsd/pd.xsd`;
- **XLSX** и **PDF** — для проверки и архива.

Готовый файл: `build/FinIskaziCG.epf` (на сервере: `C:\scripts\fi-epf\build\FinIskaziCG.epf`).
Работает во всех базах кластера (конфигурация везде одна).

## Как пользоваться (бухгалтеру)

1. В 1С: **Файл → Открыть** → `FinIskaziCG.epf`.
2. Указать **Организацию** и **Год**, при необходимости раскрыть группу «Заглавље»
   и заполнить шифру дјелатности, матични број, лицо-составителя, ответственное лицо.
3. **Заполнить** — считает все секции из ОСВ МСФО (текущий и прошлый год).
4. **Проверить** — контроли: актив=пассив по колонкам, сверка групповых итогов,
   сходимость формул. Если актив≠пассив — проблема в данных регистра МСФО
   (не проведена трансляция/закрытие) — чинить в учёте, не в обработке.
5. Вкладки/группы: **Корекције** — ручные поправки строк (секция, ред. брой, колонка,
   сумма); **PD** — строки декларации (авто-строки пересчитываются, ручные — вводить);
   **Капитал / Амортизација** — таблицы, заполняемые вручную.
6. Кнопки выгрузки: **XML ФИ / XML ПД / Excel / PDF** → файлы в указанном каталоге.
7. XML импортируется на портале (нужен сертификат).

Что заполняется автоматически: bilans stanja, bilans uspjeha, statistički aneks
(по счетам), формулы всех секций, PD (перенос прибыли/убытка, формульные цепочки,
прогрессивный налог 9/12/15%). Что руками: tokovi gotovine, promjene kapitala,
obračun amortizacije (гр. I–V), корректировки PD (usklađivanja, переносы убытков PG1/PG2),
разнесение «(dio)»-счетов (по умолчанию вся сумма падает в первую строку группы —
см. `mapping/mapping_notes.md` §6).

## Структура

- `src/` — исходники обработки (формат XML-выгрузки 1С 8.3, version 2.17/2.20):
  корень + `Ext/ObjectModule.bsl` (вся логика) + `Forms/` (управляемая форма) +
  `Templates/` (шаблоны fi.xml/pd.xml налоговой, mapping.json, правила PD).
- `mapping/` — `mapping.json`: правила «строка отчёта → счета/сальдо/формула» (315 строк),
  сгенерированы из шаблона налоговой; `apply_defaults.py` — дефолтные разнесения dio-счетов;
  `mapping_notes.md` — семантические заметки и все спорные места.
- `research/` — `fi_columns.md` (семантика колонок по Pravilnik-у), `pd_lines.md`
  (построчная семантика PD с формулами из официальной инструкции).
- `ficalc/` — независимый C#-расчётчик (кросс-проверка обработки: оба движка должны
  сходиться в 0.00 по всем строкам).
- `verify/` — `compare.py` (сверка движков), `validate.sh` (xmllint по XSD).
- `reference/` — контни оквир из прода, эталоны формата, тестовые утилиты.

## Сборка и тесты (разработчику)

```bash
./build.sh          # заливка src → 1cv8 DESIGNER на сервере → build/FinIskaziCG.epf
```

Сборка идёт против реальной базы (`BUILD_BASE=base_m` по умолчанию) — нужен контекст
конфигурации для типов; базу она не меняет. Ошибки дизайнера — в выводе.

Headless-тест (на сервере): `C:\scripts\inspect1c\runepf\...\RunEpf.exe <база> <epf> <организация> <год> <каталог>`
— подключает epf через COM (только через временное хранилище — по пути файла rphost не读 может),
вызывает `ЗаполнитьПоПараметрам`, `ПроверитьКонтроли`, все выгрузки, снимает JSON строк.
Кросс-проверка: `FiCalc.exe` тем же маппингом + `verify/compare.py`.

Грабли, уже собранные (не наступать повторно):
- Ресурс регистра МСФО — `СуммаВВалютеОтчетности` (не `Сумма`); измерение `Сценарий`
  фильтруется по наименованию «Факт».
- Условие в вирт. таблицах: `Остатки(&М, , , Организация=&Орг)`, `Обороты(&Н,&К, , , , Организация=&Орг, , )`.
- `Формат(0, ...)` в 1С = пустая строка → в форматной строке обязателен `ЧН=0.00` (pd.xsd строгий).
- Все исходники — UTF-8 **с BOM** (build.sh добавляет сам, включая Templates/*.txt —
  без BOM дизайнер читает их как cp1251 и латиница š/č/ć превращается в кашу).
- Имена функций BSL не могут совпадать со встроенными (`КонецГода` → «Ожидается имя функции»).
- Управляемая форма: version 2.20, порядок секций и обязательные ContextMenu/ExtendedTooltip —
  по эталону `reference/etalon_form.xml` (выгружен дизайнером из конфигурации).

## Ограничения v1 / план v2

- Tokovi gotovine и promjene kapitala можно автоматизировать (корреспонденции регистра
  и обороты 3xx по колонкам из `research/fi_columns.md`).
- Amortizacija (налоговые группы I–V) — данных в МСФО-регистре нет, нужен источник
  (регистр ОС РСБУ + переклассификация) либо ручной ввод (текущее решение).
- Колонка Iznos3 bilansa stanja (початак претходне године) — только при ретроспективном
  пересчёте, вводится корректировками.
- Поля pd.xsd `Iznos18c/56a/56b/59` отсутствуют на официальном бланке 114/24 — выгружаются нулями.
